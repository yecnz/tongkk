# 연결된 개념 자동 학습

자료에서 추출한 개념을 바탕으로 학습 순서를 정한다. 사용자가 같은 개념·선수 관계를 이해하고 수동으로 연결할 필요가 없다. 개념 지도에서 ‘추천 순서로 학습하기’를 누르면 설명 읽기 → 자기 설명 → 확인 문제 → 다음 개념으로 이어진다. 기존 수동 연결 데이터와 원문별 학습 이력은 보존한다.

## 연결과 순서

- 같은 과목의 개념 중 원문 근거 구간이 겹치거나 인용문이 다른 개념을 언급하면 관련 개념으로 연결한다. 인접 페이지나 이름 유사성만으로 선수 관계를 추정하지 않는다.
- 같은 이름과 충분한 길이의 동일한 원문 정의가 확인되면 같은 개념으로 묶는다. 과목별 답변·평가·복습 기록과 상태는 합치지 않는다.
- 저장된 선수 관계를 우선하고, 연결된 범위에서 보완이 필요한 개념을 먼저 배운다. 목표를 포함해 최대 12개 개념을 준비한다. 이미 안정적인 관련 개념은 생략하고, 사용자가 지정한 목표는 다시 학습할 수 있다.
- 자료가 바뀐 개념은 연결·학습 대상에서 제외한다. 근거가 부족한 개념의 관계는 추측하지 않는다. 추가 모델 호출은 발생하지 않는다.

## 저장과 복구

`learning_study_paths`와 `learning_study_path_steps`에 학습 순서, 위치와 세션을 보관한다. URL의 `path`로 재개한다. 같은 요청을 반복하거나 여러 탭에서 시작해도 같은 진행 중인 순서와 개념 세션을 사용한다. 모든 단계의 세션은 `familiarity=new`로 시작하고, 원래 원문·질문·평가 기준을 재사용한다. 설명을 보고 시작한 사실은 기존 평가 정책대로 기록한다.

현재 세션과 모든 학습 항목이 완료돼야 다음으로 진행할 수 있다. 다음 요청에 현재 위치를 보내므로 재시도해도 두 단계를 건너뛰지 않는다. 중도 종료하거나 자료가 바뀌면 새로운 시작 요청에서 기존 순서를 무효화하고 최신 자료로 새 순서를 만든다. 학습 데이터 초기화와 원문 삭제에 따른 정리도 기존 소유권·삭제 흐름을 따른다.

## 적용

프런트엔드·서버 배포 전에 `supabase/migrations/202611260001_connected_learning.sql`을 적용해야 한다. 새 설치용 `supabase/schema.sql`에도 동일한 정의를 포함했다. 새 테이블과 RPC는 서버 역할만 접근할 수 있다.

브라우저 QA는 `scripts/learning-guide-preview`의 명시된 예시 데이터로 진행한다. 실제 DB 규칙은 PGlite 격리 PostgreSQL 검사, 서버 동작은 Python 테스트로 확인한다. 운영 DB에 마이그레이션을 적용하거나 실제 사용자 기록을 바꾸는 작업은 이 변경에 포함하지 않는다.
