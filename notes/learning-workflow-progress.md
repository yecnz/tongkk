운영 DB 적용·외부 서비스 연결·배포 상태는 코드 구현과 별도로 기록한다.

1단계 검증: 타입 검사, 관련 프론트 8개 테스트, 변경 파일 ESLint 통과. 의존성 설치 폴더의 중복 타입 디렉터리는 npm ci로 복구했다.

2단계: 세션 평가 근거의 원자적 누적, 개념별 이슈·이력·버전 충돌, 기존 오답의 수동 개념 연결, 새 문항 식별자를 추가했다. 기존 클라이언트 채점은 확인 필요 근거로 보존한다. 타입·ESLint·서버 관련 34개·DB 90개 검사 통과. 운영에는 007 마이그레이션 적용이 필요하다.

3단계: 완료 기록에서 설명 다듬기, 원본·수정본·기준별 평가와 변경 비교, 초안 저장·충돌 복원·제출 재전송, 불변 제출 이력을 추가했다. 타입·ESLint·관련 프론트 12개·서버 5개·DB 106개 검사 통과. 운영에는 008 마이그레이션 적용이 필요하다.

4단계: DB 작업 큐·lease·재시작 복구 워커, 자동 복습 동의·시간대, 복습 일시 정지·미루기·캘린더, 로그아웃 초안 정리를 추가했다. 워커는 API와 함께 LEARNING_WORKER_ENABLED=true로 운영해야 한다. 타입·ESLint·서버 관련 36개·DB 125개 검사 통과. 운영에는 009 마이그레이션과 별도 워커 실행이 필요하다.

5단계: 공용 메이트가 자료·이슈 문맥을 등록하고 기존 튜터 UI·대화 저장을 재사용한다. 새 경로는 서버에서 소유권·원문 해시·검색 근거를 확인한다. 대화는 과목·자료·원문 버전으로 분리했다. 평가 중 서버 도움 제한·시험 잠금 순서 검사를 추가했다. 타입·ESLint·관련 프론트 15개·서버 11개·DB 128개 검사 통과. 운영에는 010 마이그레이션 적용이 필요하다.

6단계: 업로드 후 선택한 준비 예약, 자료별 준비·초안·폐기·최대 3회 명시적 재시도·한 번 적용을 연결했다. 생성은 기존 검증된 모델 경로와 요약 식별 키를 재사용하고, 설명 pack은 제목만 공개한다. 원문 변경·하루 준비량 제한을 적용했다. 타입·ESLint·새 프론트 2개·관련 서버 6개·DB 144개 검사 통과. 운영에는 011 마이그레이션과 활성 워커가 필요하다.

7단계: 통계에 개념별 수행·도움·서로 다른 독립 질문·지연 복습·설명 수정 이력을 추가하고 미해결 이슈를 브리핑에 연결했다. 원문 버전·신고·불확실한 레거시 근거를 구분하며 확정 보완 근거를 불확실한 후속 기록으로 지우지 않는다. 집계는 원본에서 재계산되는 뷰이며 전 과목 개념 병합·선수 그래프는 후속 범위다. 타입·ESLint·관련 프론트 2개·DB 149개 검사 통과. 동기화 폴더의 중복 타입 디렉터리를 피하도록 TypeScript 자동 전역 타입 검색 범위를 명시했다. 운영에는 012 마이그레이션 적용이 필요하다.

8단계: Google Calendar 읽기 전용 OAuth 연결, 사용자·연결에 묶은 암호화 자격 증명, 토큰 갱신·페이지 전체 가져오기·반복 인스턴스·종일 일정·과목 연결·해제를 구현했다. OAuth 콜백은 Supabase 로그인과 분리했다. 외부 원본 쓰기·상시 자동 동기화는 범위에서 제외한다. 암호화·공급자 HTTP는 대체한 서버 7개, 인증 회귀 프론트 25개, DB 178개·타입·ESLint 통과. 잠금 파일은 오프라인으로 재생성했으며 해상된 버전 변경은 없다. 운영에는 013 마이그레이션, OAuth 앱·키·정확한 callback URI·워커 설정이 필요하다. 실제 Google 계정 연결·운영 동기화는 아직 수행하지 않았다.

9단계: 응답 유실 뒤 설명 제출 상태 복원, 다른 과목의 같은 자료 ID를 가진 대화 보존, 사용량의 복습·설명 개선·자료 준비 분류를 보완했다. 014 마이그레이션은 오래된 작업 세대 차단, 300초 실행 lease, 실패한 pack 캐시의 승인 복구, 생성 중 pack 덮어쓰기 차단, 사용자 데이터 초기화 권한과 원문 변경 안내를 보완한다. 초기 schema.sql과 모든 신규 마이그레이션의 일치 여부를 검사한다.

## 후속 기능 확장 완료

같은 `feature/learning-workflow` 브랜치에서 시작 전 `git pull --ff-only origin feature/system-imporove`를 실행했고 최신 상태였다. 사용자가 선택한 추가 공급자는 Google Drive와 Notion이다.

- [x] 10. 개념 지도·선수 관계: `/stats?view=graph`, 사용자별 관계 저장·해제, 같은 개념을 거치는 간접 순환 차단.
- [x] 11. 과목 간 개념 연결: 같은 이름 후보 제안 → 사용자 확인 → 원문별 수행·과목·자료를 한 그룹에서 조회. 원본 개념·답변·평가를 물리적으로 합치지 않는다. 보완이 필요한 선수 개념은 대시보드에도 연결한다.
- [x] 12. 새 복습 문항: 새 사례·조건의 회상 질문, 해당 질문의 평가 기준·확인 문제를 함께 생성·저장한다. 원문 근거·이전 질문 중복 검사, 문항 ID에 답변 고정, 서버와 워커의 동일 문항 채점, 회차별 중복 제거·제한된 재시도, 예정된 자동 복습의 새 문제 준비를 구현했다.
- [x] 13. 캘린더 자동 동기화: 마이페이지에서 동의·주기 설정, 별도 워커의 영속 예약 검사, 중복 등록 방지·실패 backoff·성공 복원·연결 해제 중단을 구현했다.
- [x] 14. Google Drive·Notion 자료 연동: 개별 OAuth·토큰 암호화·갱신·연결 해제, 검색·페이지 이동, 과목 선택, 본문 검토·초안 폐기·한 번 적용, 변경된 원문의 새 자료 버전 저장을 구현했다. 가져오는 동안 원문이 바뀌거나 연결이 해제되면 저장을 거부한다.

추가 마이그레이션: 015 개념 관계, 016 새 복습 문항, 017 자동 동기화, 018 자료 공급자. 기존 DB의 015~018 순차 적용과 API·워커 재시작이 필요하다. Drive·Notion 각각의 OAuth 앱·callback·암호화 키 설정은 `server/README.md`, `server/.env.example`에 정리했다.

확인한 범위와 한계:

- 기존 퀴즈·복습·인증·원문별 이력을 유지하면서 확장했다. 직접 확인한 관계만 추천에 사용한다. 같은 이름만으로 다른 과목의 의미까지 같다고 확정하지 않는다.
- 새 문제의 구조·원문 인용·중복·제출 복구는 검증했다. 모델이 작성한 문항의 교육적 품질은 실제 모델·자료로 별도 확인해야 한다.
- Drive는 Google 문서 텍스트·UTF-8 텍스트/Markdown·PDF·PPTX·DOCX 본문을 지원한다. 최대 10MB이며 PDF/PPTX/DOCX는 기존 변환 도구 설정을 사용한다. 원본 바이너리는 복사하지 않는다.
- Notion은 허용한 페이지의 텍스트·중첩 블록·표·코드·수식을 지원한다. 첨부·이미지·임베드 제외를 표시하고 하위 페이지는 별도 선택한다. 한도를 넘는 본문은 부분 저장하지 않는다.
- 실제 서비스 계정 연결·공급자 승인·운영 DB 적용·배포는 수행하지 않았다. 공급자 HTTP는 고정 응답, DB는 자격 증명 없는 격리 PostgreSQL에서 확인했다.

확장 후 최종 로컬 검증: 프론트 26개 파일·166개 테스트, 서버 259개 테스트, 기존 DB 순차 변경 200개·새 설치 전체 schema 58개 검사, 고정 품질 회귀 17/17 통과. TypeScript·ESLint·색상 규칙·프로덕션 빌드 통과. 기존 Quiz Hook 경고 4개·번들 크기 경고·라이브러리 사용 중단 예정 경고는 유지된다. 브라우저에서는 개념 지도 탭의 진입·선택 상태·게스트 안내를 확인했고, 로그인한 화면 동작은 고정 사용자/HTTP 응답의 DOM·API 테스트로 검증했다. 실제 계정·실제 모델을 사용한 전체 흐름 검증을 완료했다고 표시하지 않는다.
