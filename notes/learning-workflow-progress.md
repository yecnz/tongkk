운영 DB 적용·외부 서비스 연결·배포 상태는 코드 구현과 별도로 기록한다.

1단계 검증: 타입 검사, 관련 프론트 8개 테스트, 변경 파일 ESLint 통과. 의존성 설치 폴더의 중복 타입 디렉터리는 npm ci로 복구했다.

2단계: 세션 평가 근거의 원자적 누적, 개념별 이슈·이력·버전 충돌, 기존 오답의 수동 개념 연결, 새 문항 식별자를 추가했다. 기존 클라이언트 채점은 확인 필요 근거로 보존한다. 타입·ESLint·서버 관련 34개·DB 90개 검사 통과. 운영에는 007 마이그레이션 적용이 필요하다.

3단계: 완료 기록에서 설명 다듬기, 원본·수정본·기준별 평가와 변경 비교, 초안 저장·충돌 복원·제출 재전송, 불변 제출 이력을 추가했다. 타입·ESLint·관련 프론트 12개·서버 5개·DB 106개 검사 통과. 운영에는 008 마이그레이션 적용이 필요하다.

4단계: DB 작업 큐·lease·재시작 복구 워커, 자동 복습 동의·시간대, 복습 일시 정지·미루기·캘린더, 로그아웃 초안 정리를 추가했다. 워커는 API와 함께 LEARNING_WORKER_ENABLED=true로 운영해야 한다. 타입·ESLint·서버 관련 36개·DB 125개 검사 통과. 운영에는 009 마이그레이션과 별도 워커 실행이 필요하다.

5단계: 공용 메이트가 자료·이슈 문맥을 등록하고 기존 튜터 UI·대화 저장을 재사용한다. 새 경로는 서버에서 소유권·원문 해시·검색 근거를 확인한다. 대화는 과목·자료·원문 버전으로 분리했다. 평가 중 서버 도움 제한·시험 잠금 순서 검사를 추가했다. 타입·ESLint·관련 프론트 15개·서버 11개·DB 128개 검사 통과. 운영에는 010 마이그레이션 적용이 필요하다.

6단계: 업로드 후 선택한 준비 예약, 자료별 준비·초안·폐기·최대 3회 명시적 재시도·한 번 적용을 연결했다. 생성은 기존 검증된 모델 경로와 요약 식별 키를 재사용하고, 설명 pack은 제목만 공개한다. 원문 변경·하루 준비량 제한을 적용했다. 타입·ESLint·새 프론트 2개·관련 서버 6개·DB 144개 검사 통과. 운영에는 011 마이그레이션과 활성 워커가 필요하다.

7단계: 통계에 개념별 수행·도움·서로 다른 독립 질문·지연 복습·설명 수정 이력을 추가하고 미해결 이슈를 브리핑에 연결했다. 원문 버전·신고·불확실한 레거시 근거를 구분하며 확정 보완 근거를 불확실한 후속 기록으로 지우지 않는다. 집계는 원본에서 재계산되는 뷰이며 전 과목 개념 병합·선수 그래프는 후속 범위다. 타입·ESLint·관련 프론트 2개·DB 149개 검사 통과. 동기화 폴더의 중복 타입 디렉터리를 피하도록 TypeScript 자동 전역 타입 검색 범위를 명시했다. 운영에는 012 마이그레이션 적용이 필요하다.

8단계: Google Calendar 읽기 전용 OAuth 연결, 사용자·연결에 묶은 암호화 자격 증명, 토큰 갱신·페이지 전체 가져오기·반복 인스턴스·종일 일정·과목 연결·해제를 구현했다. OAuth 콜백은 Supabase 로그인과 분리했다. 외부 원본 쓰기·상시 자동 동기화는 범위에서 제외한다. 암호화·공급자 HTTP는 대체한 서버 7개, 인증 회귀 프론트 25개, DB 178개·타입·ESLint 통과. 잠금 파일은 오프라인으로 재생성했으며 해상된 버전 변경은 없다. 운영에는 013 마이그레이션, OAuth 앱·키·정확한 callback URI·워커 설정이 필요하다. 실제 Google 계정 연결·운영 동기화는 아직 수행하지 않았다.
