# tongkk 튜토리얼 개편 플랜 — 핵심 흐름(자료→요약→퀴즈) 중심 맥락형 온보딩

> 작성일: 2026-06-13 · 기준 브랜치: `refactor`
> 목표: "첫 화면 1회 4단계 모달"을 폐기하고, **자료 이해의 핵심 흐름(자료 업로드 → AI 요약 → 자료 이해 → 퀴즈)**만 화면 진입 시점에 맥락형으로 안내한다. 한 번 본 안내는 강요하지 않되 언제든 다시 볼 수 있어야 한다.

---

## 0. 스코프 결정 (이번 개정의 핵심)

튜토리얼은 **무엇이든 다 알려주는 것**이 아니라, **신규 사용자가 막히는 핵심 가치 경로**에만 집중한다.

| 구분 | 화면/기능 | 처리 |
|------|-----------|------|
| ✅ **튜토리얼화 (핵심 흐름)** | 진입 on-ramp(강의 추가·자료 올리기), **자료 요약**(업로드·생성·자료 이해), **퀴즈**(설정·풀이) | 맥락형 튜토리얼 + 상시 `?` |
| ❌ **제외 — 플래닝** | **D-day 등록**, **AI 학습계획**, 학습 캘린더(할 일·페이스) | 안내하지 않음(인앱 placeholder만 유지) |
| ❌ **제외 — 진입 시 직관적** | **오답 노트**, **학습 통계**, **마이페이지**, **AI 튜터** | 안내하지 않음(필요 시 빈 상태 문구 정도) |

**근거**: ① 플래닝(D-day/학습계획)은 부가 기능이라 핵심 가치 입증 전에 가르치면 정보 과부하다. ② 오답 노트·통계·마이페이지·AI 튜터는 진입하면 라벨·레이아웃만으로 의도가 읽혀, 별도 안내 없이도 사용 가능하다. ③ 반면 **자료 요약·퀴즈는 사이드바에서 숨겨져 있고(`common.tsx` filter) 동작도 비자명**(다중 자료 압축, 시험 모드, AI 채점 대기 등)해 안내가 가장 필요하다.

> 직전 버전 대비 변경: 글로벌 인트로 축소, 대시보드는 **on-ramp 1스텝**으로 감축, **캘린더·오답·통계·마이페이지·AI튜터 튜토리얼 전면 삭제**, 학습계획 관련 보조 기능(소스 피커 가이드·페이스/진척도 툴팁) 삭제.
>
> 이번 개정: 사이드바 '앱 사용법 다시 보기' 행 제거 → **'예시로 둘러보기'(우리가 지정한 샘플 자료) 중심**으로 전환. 보조 기능은 6.2·6.3·6.4(샘플)·6.5만 유지. **퀴즈 생성은 자료 필수**로 변경. 생성 안내 문구를 '기다려 주세요'식에서 '직관적 기능 설명'식으로 교체.

## 1. 배경과 현황 진단

| 항목 | 현재 상태 | 문제 |
|------|-----------|------|
| 온보딩 | `OnboardingModal.tsx` `OnboardingGate` — 비로그인 첫 방문자에게 **4단계 전면 모달 1회** | 첫 화면에서 전부 설명(progressive onboarding 위반). 로그인 사용자는 아예 못 봄 |
| 재열람 | **없음** — `grep` 결과 앱 전역에 `도움말/튜토리얼/다시 보기/?` 진입점 0건 | '건너뛰기'로 닫으면 영영 다시 못 봄 |
| 진입 경로 | 사이드바가 `자료 요약`·`퀴즈 생성`을 **숨김**(`common.tsx` filter) | 핵심 두 화면은 강의/자료 흐름 안에서만 열려서, 처음 사용자가 진입 경로를 못 찾음 |
| 발견성 낮은 기능 | 다중 자료 압축, 마인드맵 학습 모드, 시험 모드, 주관식 AI 채점 대기 등 | 시각 단서가 없어 존재·동작을 모름 |

**핵심 흐름 의존 사슬(튜토리얼 순서의 근거)**: `강의 추가 → 자료 업로드 → AI 요약 → 자료 이해 → 퀴즈`. 이 사슬만 튜토리얼이 따라간다.

## 2. 설계 원칙 (확정)

1. **핵심 흐름만, 맥락형·점진적**: 첫 화면에서 전부 알려주지 않는다. 자료→요약→퀴즈 경로의 그 화면에 들어올 때 그 화면 얘기만 한다.
2. **must만, 3~5스텝, 한 스텝 1~2문장**: 한 말풍선에 여러 동작을 욱여넣지 않는다. 부차 기능은 인앱 인라인 힌트·`?` 도움 패널로 위임.
3. **비강압이 기본**: 화면 전체를 가리는 라이트박스 대신 상단/우하단 안내 시트. 닫기 쉬움.
4. **재열람은 항상 살아있음**: 핵심 흐름 화면 헤더 `?` + 마이페이지 허브. '다시 보지 않기' 같은 영구 차단 체크박스 금지.
5. **MEMORY/디자인 규칙 준수**: 왼쪽 색상 띠 금지 → 흰 배경 + 사방 중립 테두리. 후보 일일이 체크 강요 금지. 다크모드 저채도 토큰. 인라인 hex 금지(`var(--color-*)`만). 화면 배율(전역 0.90 + `tongkk-ui-scale`) 상쇄 금지.
6. **게스트/로그인 양립**: 트리거는 `user` 유무와 무관, **콘텐츠만 분기**.

## 3. 알려줄 기능 — 핵심 흐름 화면별 must 목록

| 화면 | must (튜토리얼 본문) | 인라인 힌트/도움 패널로 위임 |
|------|---------------------|------------------------------|
| **글로벌 첫 진입** | 앱이 뭐 하는 곳인지 / 시작 흐름(과목→자료→요약→퀴즈) / 로그인·가입 진입 | 사이드바 이동 |
| **진입 on-ramp `/`** | 강의 추가(+자료 올리기) — 핵심 흐름의 입구 1개만 | (D-day·학습계획·공부 시작 카드는 안내 안 함) |
| **자료 요약 `/summary`** | (업로드) ① 자료 올리기/텍스트 붙여넣기 ② 반영 자료 선택 ③ 요약 종류·생성 / (이해) ④ 원본·요약·퀴즈 탭으로 학습 | 마인드맵 학습 모드, ☰ 요약 목록, PDF는 인쇄창에서 저장, 다중 자료 압축, 본문 드래그 질문 |
| **퀴즈 `/quiz`** | (설정) ① 자료 선택(필수) ② 시험 모드 ③ AI가 자료 분석해 생성 / (풀이) ④ 채점·답변 변경 불가·주관식 AI 채점 | 페이스메이커, 결과 화면 오답 복습 |

> **제외**: 학습 캘린더, 오답 노트, 학습 통계, 마이페이지, AI 튜터 — 튜토리얼 없음.

## 4. 핵심 흐름 화면별 맥락형 튜토리얼 설계

각 항목: **키 / 트리거 / 형식 / 스텝(마이크로카피) / 빈 상태 / 상시 도움**. 마이크로카피는 그대로 구현에 쓸 수 있는 한국어 초안이다.

### 4.0 글로벌 첫 진입 — `welcome` (슬림 2스텝 + 예시 둘러보기)
- **트리거**: 비로그인으로 앱 첫 진입 + `seen.welcome` 없음. (기존 `OnboardingGate` 조건 계승, **4단계 → 2단계 축소**)
- **형식**: 기존 `OnboardingModal` 골격 재사용(토큰·점 인디케이터·페이저 보유). 자동 사이드바 스포트라이트는 만들지 않는다(첫 세션 강제 투어 방지).
- **스텝**
  1. **Tongkk가 뭐예요?** — 강의 자료(PDF·PPT·이미지·텍스트)를 올리면 AI가 강의 노트·치트시트·마인드맵으로 요약하고, 퀴즈까지 만들어줘요.
  2. **이렇게 써요** — ① 과목 만들기 → ② 자료 올리기 → ③ AI 요약으로 이해 → ④ 퀴즈로 점검. '자료 요약·퀴즈'는 과목 안에서 열려요.
- **버튼**: 기본 '시작하기'(→ 로그인) + 보조 **'예시로 둘러보기'**(→ 우리가 지정한 샘플 자료로 요약·퀴즈 결과를 미리 체험, 6.4). 글을 읽는 대신 실제 산출물을 보여줘 이해시킨다.
- **상시 도움/재열람**: 사이드바에 '앱 사용법 다시 보기' 행은 **두지 않는다.** 대신 어디서든 **'예시로 둘러보기'(6.4)**로 핵심 흐름을 다시 체험하고, 화면별 사용법은 자료 요약·퀴즈 헤더의 `?`로 다시 본다.

### 4.1 진입 on-ramp — `dashboard` (1스텝)
> 대시보드를 통째로 가르치지 않는다. **핵심 흐름의 입구**(강의 추가 → 자료 올리기)만 짚는다. D-day·AI 학습계획·공부 시작 카드는 안내하지 않는다.
- **트리거**: `/` 첫 진입 + `seen.dashboard` 없음 + 데이터 준비 완료 후(`ready('dashboard')`). 인증 게이트 모달 떠 있으면 보류.
- **형식**: 강의 그리드 영역을 가리키는 상단 안내 시트(또는 빈 상태 '+ 강의 추가하기' 앵커).
- **스텝**
  1. **여기서 강의를 만들고 자료를 올려요** — 과목을 추가하고 강의자료를 올리면 AI가 요약·퀴즈를 만들 준비를 해요. '추가하고 자료 올리기'를 누르면 바로 업로드로 이어져요. *(게스트면: "(저장하려면 로그인이 필요해요)")*
- **상시 도움**: 헤더 `?`(이 1스텝 + '자료 요약·퀴즈는 강의 안에서 열려요' 안내).

### 4.2 자료 요약 — `summary-upload` + `summary-result` (2키 분리)
> ⚠️ 상태별 키 분리: `markSeen`이 한 번 일어나면 결과 단계를 영영 못 보는 사각지대를 막기 위함.

- **`summary-upload`** — `/summary` 첫 진입 시(로그인+과목 선택 전제, 게스트는 진입 즉시 대시보드 리다이렉트).
  1. **자료를 올려 시작하기** — PDF·PPT·DOCX·TXT·이미지를 끌어다 놓거나 '파일 선택'으로 올리면 AI가 읽어요. 파일이 없으면 '텍스트 붙여넣기' 탭에 필기를 붙여넣어도 돼요.
  2. **요약에 반영할 자료 고르기** — 기본은 최근 자료 1개. 행을 눌러 여러 개를 묶으면 AI가 내용을 줄여 요약해요(한 강의 집중은 1개).
  3. **종류를 고르고 생성하기** — 일반 요약·강의 노트·마인드맵·치트시트 중 골라 '요약 생성하기'. 만드는 동안 다른 화면으로 가도 완료되면 알려드려요.
- **`summary-result`** — 요약 결과 뷰가 처음 렌더될 때(`maybeShow('summary-result')`). **자료 이해**에 집중.
  4. **만든 요약으로 학습하기** — 원본·요약·퀴즈 탭을 오가며 봐요. 마인드맵은 '학습 모드'를 켜면 노드를 눌러 더 펼쳐 볼 수 있고, 요약이 여러 개면 ☰로 전환해요.
- **빈 상태(드롭존 상시 문구)**: "지원 형식: PDF·PPT/PPTX·DOCX·TXT·MD·이미지 · 여러 개 동시 OK · 50MB 초과 시 원본 없이 텍스트만 저장돼요".
- **상시 도움**: 헤더 `?` — 발견 어려운 팁(마인드맵 학습 모드, PDF는 인쇄창에서 저장, 다중 자료 압축, 본문 드래그로 질문) 목록 포함.

### 4.3 퀴즈 — `quiz-setup` + `quiz-solve` (2키 분리)
> 설정→풀이는 시점이 다르므로 키 분리. 오답 다시 풀기/저장된 풀이 열람으로 설정을 건너뛴 진입에서도 `quiz-solve`는 (첫 풀이라면) 떠야 한다. **퀴즈 결과 화면은 진입 시 직관적이라 별도 튜토리얼 없음.**
> ⚠️ **제품 동작 변경**: 퀴즈 생성은 이제 **자료가 있어야** 가능하다(과목명만으로 생성하는 경로 제거). `Quiz.tsx`의 생성 가드를 '자료 1개 이상 선택'으로 바꾸고, 자료 0개면 '퀴즈 생성하기' 비활성 + 안내. 이 변경이 1단계 마이크로카피의 전제다.

- **`quiz-setup`** — 외부 진입점(대시보드 과목 카드/요약의 '퀴즈 생성')으로 설정 화면 첫 도달 시.
  1. **자료를 올려 퀴즈를 만들어요** — PDF·PPT·이미지·문서를 올리면 그 자료 내용으로 문제를 만들어요. 자료를 골라야 생성할 수 있어요.
  2. **시험 모드는 실전처럼** — 켜면 정답·해설이 바로 안 보이고 제한 시간 안에 전체를 풀어요. 시간 버튼은 모드를 켜야 활성화돼요.
  3. **AI가 자료를 분석해 문제를 만들어요** — '퀴즈 생성하기'를 누르면 AI가 자료를 읽고 문제를 만들어요. 이전에 푼 문제는 자동으로 빼 줘요.
- **`quiz-solve`** — `view==='quiz'` 첫 진입 시(설정 건너뛴 진입 포함). 인라인 마이크로코치 1장.
  4. **풀이 화면 사용법** — 객관식·OX는 보기를 누르면 바로 채점되고 다시 못 바꿔요. 단답형은 Enter/제출, 주관식은 제출하면 AI가 채점해요. (시험 모드는 결과에서 한꺼번에 확인)
- **빈 상태/진입 유도**: 직접 URL·게스트는 대시보드로 리다이렉트되므로, 과목 카드에 "과목을 고르고 자료를 올리면 AI 퀴즈를 만들 수 있어요" 진입 힌트. 자료 0개면 생성 비활성 + "자료를 먼저 올려주세요".
- **상시 도움**: 설정 화면 헤더 `?`(설정+풀이 사용법 미리보기 포함).

### 4.4 비-라우트 진입 화면 — 인라인 힌트 (핵심 흐름 관련만)
> 라우트가 아니어서 `useLocation` 트리거 대상이 아닌 모달은 `maybeShow(key)`로 동일 파이프라인·동일 저장 정책(`tongkk-tutorial-seen`)을 쓴다. **핵심 흐름과 무관한 페이스 모달 등은 다루지 않는다.**

| 화면 | 키 | 트리거 | 안내(1회 인라인 힌트) |
|------|----|--------|----------------------|
| 강의 추가 모달 | `addcourse` | 모달 오픈 시 | "'추가만 하기'는 빈 과목만, '추가하고 자료 올리기'는 바로 업로드로 이어져요" |
| 강의 상세 모달 | `coursedetail` | 오픈 시 | "자료 행을 누르면 상세, 아래 버튼으로 요약·퀴즈를 만들어요" |

## 5. 전달 아키텍처 (기술 설계 — 코드로 검증됨)

### 5.1 컴포넌트/모듈
| 이름 | 책임 |
|------|------|
| `TutorialProvider` | `useLocation`으로 라우트 첫 진입 감지 → `ROUTE_TO_TUTORIAL` 매핑 → `seen` 검사 → 미열람이면 활성화. `open/close/maybeShow/ready` context 노출. ref로 마운트당 1회 트리거(StrictMode 안전). 활성 시 `TutorialSheet`를 portal로 렌더. |
| `useTutorial(key?)` | 헤더 `?`의 `open(key)`, 비라우트의 `maybeShow(key)`, 라우트의 `ready(key)`(데이터 준비 푸시) 진입점. |
| `TutorialSheet` | 표현 컴포넌트. steps를 `STEP n/N` 페이저로 한 장씩. **흰 배경 + 사방 중립 테두리**, 토큰 색만. 닫힐 때 `onDismiss`로 `markSeen`. 앵커 스텝만 요소 근처 말풍선, 없으면 고정 시트. |
| `TutorialHelpButton` | 핵심 흐름 페이지 헤더 원형 `?`. 현재 화면 투어 재생(`seen` 미변경). |
| `tutorialStorage` | `localStorage 'tongkk-tutorial-seen'` JSON 묶음 단일 게이트. `hasSeen/markSeen/resetAll`. 전부 try/catch(프라이빗 모드 폴백). |
| `TUTORIALS` | 콘텐츠 레지스트리(코드 분리). `key → { version, requiresAuth?, requiresCourse?, route?, steps:[{title,body,anchorSelector?,guestBody?}] }`. **키 집합: `welcome`,`dashboard`,`summary-upload`,`summary-result`,`quiz-setup`,`quiz-solve`,`addcourse`,`coursedetail`** (그 외 화면 없음). |

> `OnboardingModal.tsx`는 `TutorialSheet`로 흡수 후 삭제.

### 5.2 트리거 모델
- `ROUTE_TO_TUTORIAL` 매핑은 **`/`→dashboard, `/summary`→summary-upload, `/quiz`→quiz-setup 만** 둔다. `/calendar`·`/review`·`/stats`·`/mypage`는 매핑 없음(no-op). `common.tsx`의 `pageRoutes`를 라우트 단일 출처로 재사용.
- navigation 직후 `requestAnimationFrame`로 한 박자 늦춰 표시(스켈레톤 위 노출 방지).
- `summary-result`/`quiz-solve`는 해당 뷰 진입 시 `maybeShow`로 합류.

### 5.3 본 여부 저장 — **단일 묶음 키로 확정**
- `localStorage` **단일 묶음 키** `tongkk-tutorial-seen` = `{ [key]: seenVersion }`. (서버 플래그·`UserProfile.seenTours` 폐기 — `profile.ts`에 컬럼 없음 확인, 마이그레이션 회피. 멀티 디바이스 동기화는 명시적 2차.)
- **버전**: 레지스트리 `version`. `hasSeen`은 저장 버전 ≥ 현재일 때만 true. UI 큰 변경 시에만 version↑.
- **StrictMode 안전**: 표시 시점이 아니라 **사용자 닫기 액션**에서만 `markSeen`.
- **마이그레이션**: 기존 `tongkk-onboarding-shown`은 읽지 않고 둠 → 모든 사용자가 핵심 흐름 안내 1회 수신. `OnboardingGate`만 제거.

### 5.4 트리거 타이밍 — **push 모델로 확정**
- Provider가 페이지 로컬 loading state를 끌어오지 않고, **각 라우트 컴포넌트가 데이터 준비 후 `useTutorial().ready(key)`** 호출(콜백 push). 신호 없이 일정 시간 지나면 폴백 표시. (`Dashboard.hasLoadedCourses`가 페이지 로컬 state라는 코드 확인 반영.)

### 5.5 게스트/리다이렉트 경쟁 조건
> 코드 확인: `Summary.tsx:3985`·`Quiz.tsx:1060`은 **렌더 시점 `<Navigate>`** 라, `useLocation`이 한 박자 먼저 경로를 보고 트리거를 시도할 수 있음.
- **대응**: 레지스트리 플래그 `requiresAuth`/`requiresCourse`. Provider는 게스트/과목 미선택이면 해당 키 트리거를 건너뜀(rAF 지연 병행).

### 5.6 좌표/zoom 충돌 — 앵커 최소화 (코드로 확인된 깨짐)
> `index.css:114` `#root { zoom: var(--app-scale) }`, `--app-scale:0.90`. `getBoundingClientRect`와 portal(body) 좌표계가 어긋남 — **이미 `Summary.tsx:748~814`가 `window.scrollBy(0, delta)` 수동 보정 중**.
- **대응**: 표현 기본형은 **고정 시트 + 텍스트 카피**. 좌표 앵커는 위치 의존 must 스텝에만. 필요한 앵커는 Summary의 delta 보정 로직을 **공용 유틸 `anchorRect()`로 추출**해 zoom·`tongkk-ui-scale`·Windows 배율 조합에서 검증.

### 5.7 z-index — 실측 재산정
> `grep` 확인: 최상위는 280이 아니라 **301**(AITutor 드로어), 300×3, 토스트/오버레이 1000·1100·99998.
- **확정**: `TutorialSheet` = **350**(모달 301 위, 토스트 99998 아래). 자료 요약 결과 화면에서 AI 튜터 드로어(300/301)가 열린 상태로 `summary-result` 투어가 뜰 일은 거의 없으나, 겹치면 350이 위에 보이도록 검증.

### 5.8 Provider 배치 — `/auth`까지 커버
> 코드 확인: `App.tsx`는 `/auth`와 `/*`(AppShell)가 분리. push 모델 덕에 Provider는 `useCourses` 불필요.
- **확정**: `BrowserRouter > AuthGateProvider` 안, `/auth`+`/*`를 함께 감싸는 `<Routes>` 바깥(현재 `<OnboardingGate/>` 자리)에 `TutorialProvider`. `<OnboardingGate/>` 제거.

### 5.9 접근성
- 라이트박스 모드만 `role='dialog' aria-modal='true'` + 포커스 트랩 + Esc=닫기; 비강압 시트는 `role='region' aria-label`. `STEP n/N`은 `aria-live`. 닫기/도움 버튼 `aria-label`.
- 닫을 때 트리거 요소(또는 본문 첫 요소)로 포커스 복귀. `prefers-reduced-motion` 존중. hover 힌트가 안 보이는 터치 환경을 시트가 보완.

## 부록 A — '예시로 둘러보기' 샘플 콘텐츠 명세

> **주제: 자료구조·알고리즘 — "시간 복잡도(Big-O)와 정렬 알고리즘"** (컴공 공감형, 교체 후보: 운영체제 '프로세스 vs 스레드' / 네트워크 'TCP·UDP·OSI 7계층')
> 모든 콘텐츠는 **앱에 번들된 정적 데이터**(실시간 AI 호출 없음). 게스트도 동일하게 열람, 서버 저장 없음. 결과물은 실제 `summary`/`quiz` 렌더 컴포넌트를 재사용해 "진짜 같은" 데모로 보이게 한다. 마지막에 '내 자료로 시작하기' CTA.

### A-1. 원본 강의 자료 (사용자가 '올린 것'으로 가정, ~1.5p)
- **시간 복잡도와 Big-O 표기**: 입력 크기 n에 따른 연산 증가율. $O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2)$. (→ KaTeX 렌더 시연)
- **대표 정렬 알고리즘**: 버블·선택·삽입(기초), 병합·퀵·힙(고급)의 동작 한 줄 요약.
- **선택 기준**: 데이터 크기, 안정성 필요 여부, 메모리(in-place) 제약에 따른 알고리즘 선택.

### A-2. 4종 요약 출력 (각 1개 미리보기 — 토글로 전환)
- **일반 요약**: 3~4문단. "정렬은 …, 복잡도는 …, 상황별 선택은 …" 핵심만.
- **강의 노트**: `개념(복잡도/Big-O) → 정렬별 정리(동작·복잡도·특징) → 비교·선택 기준` 구조의 불릿 노트.
- **마인드맵**: `정렬 알고리즘` 루트 → 분류축(비교기반/비비교 · 안정/불안정 · in-place 여부) → 각 알고리즘 노드. (학습 모드 켜기 힌트 동반 — 6.5)
- **치트시트**: 비교표 — `알고리즘 | 평균 | 최악 | 안정성 | in-place`(버블·선택·삽입·병합·퀵·힙) + Big-O 사다리 한 줄.

### A-3. 샘플 퀴즈 1세트 (5문항, 4유형 mix)
1. **객관식** — "평균 시간 복잡도가 $O(n\log n)$이 **아닌** 정렬은?" (① 병합 ② 퀵 ③ 힙 ④ 선택) → ④
2. **OX** — "퀵 정렬은 입력과 무관하게 항상 $O(n\log n)$이다." → X (최악 $O(n^2)$)
3. **단답형** — "병합 정렬이 추가로 쓰는 공간 복잡도는?" → $O(n)$
4. **객관식** — "안정 정렬(stable)이 **아닌** 것은?" (① 삽입 ② 병합 ③ 선택 ④ 버블) → ③
5. **주관식(AI 채점 시연)** — "퀵 정렬과 병합 정렬을 **안정성·메모리** 관점에서 비교해 설명하시오." → 데모에선 미리 작성된 모범답안 + AI 채점 예시(점수·피드백)를 보여줌.

> 이 한 세트로 `quiz-setup`(자료 필수)·`quiz-solve`(객/OX/단답/주관 채점)·결과 화면까지 핵심 흐름 산출물을 모두 시연한다.
