# 학습 기능 UI 정리

기존 마이페이지·통계·자료 화면의 디자인 규칙을 새 학습 기능에 적용했습니다. 공통 스타일은 `src/styles/learning-workflow.css`에서 관리하고 `src/index.css`에서 불러옵니다. 개별 기능을 기존 페이지 안에 넣어도 학습 전용 레이아웃의 CSS에 의존하지 않도록 구성했습니다.

## 기준과 적용

| 요소 | 적용한 규칙 |
| --- | --- |
| 글꼴 | 기존 Pretendard Variable 및 같은 시스템 글꼴 대체 순서 상속 |
| 페이지 제목 | 24px, 굵기 800 |
| 카드 제목 | 16px, 굵기 700 |
| 본문과 입력 | 14px, 모바일 입력의 기존 16px 규칙 유지 |
| 설명과 보조 정보 | 13px와 12px |
| 버튼 | 13px, 기본 굵기 600과 주요 동작 700, 최소 높이 38px, 모서리 10px |
| 카드 | 기존 공용 Card의 배경·테두리·그림자·모서리 18px, 내부 여백 24px와 모바일 20px |
| 색상 | 기존 pink·cyan·표면·텍스트·상태 토큰 재사용, 라이트·다크 전환 유지 |
| 입력과 설정 | 전체 너비 입력창, 정렬된 필드, 기존 마이페이지와 같은 크기의 토글 |
| 모바일 | 폼을 한 열로 전환, 버튼 줄바꿈, 개념 지도의 글자 크기를 유지하며 내부 가로 스크롤 |

브리핑은 제목·설명·실행 링크를 행으로 정리했습니다. 복습·이슈·개념 카드에는 상태 배지를 적용했고, 복습의 주요 실행과 보조 버튼을 한 줄에 모았습니다. 외부 서비스 연결·검색·초안 검토·저장의 각 영역을 구분하고, 자동 준비와 설명 개선도 같은 입력·버튼 규칙을 사용합니다. 마지막 학습 패널 아래에는 학습 메이트가 버튼을 덮지 않도록 여백을 둡니다.

## 확인 범위

- 실제 앱의 마이페이지에서 기존 카드 제목 16px·굵기 700, 버튼 13px, 카드 모서리 18px 및 배경색을 브라우저의 계산된 스타일로 비교했습니다.
- 예시 데이터를 사용하는 실제 구현 컴포넌트로 브리핑, 복습 목록·풀이, 학습 이슈, 자동 준비, 개념 기록·지도, 설정과 자료 연결, 학습 메이트를 확인했습니다.
- 데스크톱 기본 화면과 라이트·다크 테마를 확인했습니다. 미리보기에도 실제 앱과 같은 Pretendard 웹 글꼴을 연결했습니다.
- 390px iframe의 실제 문서 너비와 scrollWidth를 측정했습니다. 복습 설정, Calendar 연결, 복습 목록, 이슈 상세, 개념 지도·기록, 자동 준비, 복습 풀이, 설명 개선의 9개 화면에서 가로 넘침이 없었습니다. Drive의 입력창과 개념 연결 폼도 너비를 따로 확인했습니다.
- 모바일 토글 해제·재설정과 개념 선택을 UI로 조작했습니다. 이 검증은 실제 외부 계정이나 운영 학습 데이터를 사용하지 않습니다.

캡처는 `screenshots/`에 보관합니다. `review-desktop-light.jpg`는 복습 목록, `drive-desktop-light.jpg`와 `drive-mobile-light.jpg`는 외부 자료 연결, `graph-desktop-dark.jpg`는 개념 지도, `settings-mobile-dark.jpg`는 복습 설정입니다.

## 다시 확인하기

```sh
node node_modules/vite/bin/vite.js --config scripts/learning-guide-preview/vite.config.mjs
```

기능별 화면은 `http://127.0.0.1:5177/`에서 열고, 390px 반응형 확인은 `/responsive.html`에서 화면을 선택합니다. 설정·통계·자료 컴포넌트는 일반 페이지의 컨테이너 안에서, 복습·설명 개선은 실제 학습 페이지 안에서 확인합니다.

검증 결과: 프론트 26개 파일의 166개 테스트, TypeScript, ESLint와 색상 규칙, 프로덕션 빌드 및 별도 미리보기 빌드가 통과했습니다. 기존 Quiz Hook 경고 4개와 번들 크기 경고는 남아 있습니다.
